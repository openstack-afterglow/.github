## Una nueva experiencia para OpenStack

Afterglow es una organización de código abierto que desarrolla y mantiene un panel de OpenStack y servicios complementarios. Su proyecto principal, Afterglow, aspira a ser una alternativa a Horizon y Skyline: una interfaz moderna y unificada para usuarios y operadores de la nube.

Afterglow está en funcionamiento como consola de [DMS Cloud](https://cloud.dmslab.re.kr). Mejoramos el proyecto a partir de necesidades reales de operación. El acceso al servicio está sujeto a las políticas de cuentas y proyectos del operador.

## Proyectos

| Proyecto | Objetivo |
| --- | --- |
| [Afterglow](https://github.com/openstack-afterglow/openstack-afterglow) | Gestión de recursos de OpenStack e integración de servicios con SvelteKit y FastAPI |
| [Drover](https://github.com/openstack-afterglow/drover) | Ciclo de vida de clústeres K3s y grupos de nodos sobre OpenStack |
| [Palimpsest](https://github.com/openstack-afterglow/palimpsest) | Entornos de máquinas virtuales reutilizables, capas SquashFS e imágenes de arranque |
| [Lumen](https://github.com/openstack-afterglow/lumen) | Chat con IA, ejecución de agentes, herramientas, memoria y seguimiento del uso |
| [Waygate](https://github.com/openstack-afterglow/waygate) | Puertas de enlace WireGuard y configuración de clientes por proyecto |

Consulta el README de cada repositorio para conocer la instalación, los entornos compatibles, el estado de las versiones y la licencia. La madurez y el despliegue pueden variar entre componentes.

## Participa

Damos la bienvenida a desarrolladores, operadores, investigadores, diseñadores, autores de documentación y personas que contribuyen por primera vez. También puedes ayudar con accesibilidad, traducciones, pruebas, reproducción de errores y experiencias de operación.

1. Elige un repositorio y lee su README, arquitectura e instrucciones de desarrollo.
2. Revisa los issues y PR existentes. Antes de realizar cambios grandes, abre un issue para acordar el alcance.
3. Crea un fork y una rama con un cambio concreto. Ejecuta las comprobaciones documentadas y actualiza las pruebas y la documentación correspondientes.
4. Abre un pull request que explique el problema, el cambio y su validación. Incluye capturas para cambios de interfaz.

Al informar de errores, indica la versión o el commit, el entorno, el comportamiento esperado y real, y una reproducción mínima. Elimina credenciales, tokens y datos de usuarios. No necesitas ser miembro de la organización para enviar issues o PR.

Si no sabes por dónde empezar, abre un [issue de Afterglow](https://github.com/openstack-afterglow/openstack-afterglow/issues/new). Se aceptan conversaciones en coreano e inglés. También agradecemos mejoras de traducción y nuevos idiomas.

## Contribuir a OpenStack

Queremos devolver a OpenStack lo aprendido en producción mediante informes reproducibles, parches, pruebas y documentación. Los cambios destinados a proyectos upstream siguen la [guía oficial de contribución de OpenStack](https://docs.openstack.org/contributors/code-and-documentation/index.html) y el proceso del proyecto correspondiente.

Afterglow se desarrolla de forma independiente. Esta página no afirma que sea un proyecto oficial de OpenStack, que cuente con su respaldo o que sus cambios hayan sido aceptados upstream.
